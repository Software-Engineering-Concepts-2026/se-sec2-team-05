# ADR-011: จำกัดความถี่ของ login และสมัครสมาชิก โดยเก็บตัวนับใน Postgres

[🌐 English](./0011-rate-limit-login-and-register.md) · **ภาษาไทย**

**สถานะ:** Accepted

**บริบท:**
auth-service รับ `POST /auth/login` และ `POST /auth/register` ได้ไม่จำกัดจำนวน สคริปต์จึงเดารหัสผ่านของบัญชีเดียวได้เรื่อย ๆ ลองรหัสยอดนิยมตัวเดียวกับหลายบัญชี หรือไล่รายชื่ออีเมลผ่านหน้าสมัคร ซึ่งคำตอบ `409 email_taken` บอกว่าอีเมลไหนมีบัญชีแล้ว (ADR-005 ยอมรับช่องนี้ไว้เพื่อให้ตรง US-05) · บน Vercel service รันเป็นหลาย instance ที่ไม่เก็บ state และปิดตัวเองเมื่อไม่มีคนใช้ (ADR-009) ตัวนับใน memory ของ process จึงแยกกันในแต่ละ instance และเริ่มนับใหม่ทุกครั้งที่ cold start · นักศึกษาที่ใช้เน็ตของมหาวิทยาลัยอาจออกเน็ตผ่าน IP สาธารณะเดียวกัน

**การตัดสินใจ:**
*   นับในตารางใหม่ **`auth_attempts`** (kind, key, created_at) ที่สร้างด้วย Alembic revision `0002` ของ auth-service (ADR-010) · ทุก instance อ่านแถวชุดเดียวกันใน Postgres ที่ใช้ร่วมกัน (Neon) และเพดานคิดจากหน้าต่างเวลาที่เลื่อนไปเรื่อย ๆ บนแถวเหล่านั้น
*   **login:** นับครั้งที่ login ไม่ผ่านต่ออีเมลที่ส่งมาและต่อ IP ของผู้ใช้ · ค่า default คือ 5 ครั้งต่ออีเมลและ 30 ครั้งต่อ IP ใน 15 นาที · ครบเพดานตัวใดตัวหนึ่งแล้วตอบ **`429`** พร้อม `Retry-After` และข้อความไทยบอกจำนวนนาทีที่ต้องรอ **ก่อน** ตรวจรหัสผ่าน ช่วงนั้นแม้รหัสถูกก็เข้าไม่ได้ · อีเมลที่ไม่มีบัญชีก็ถูกนับและล็อกแบบเดียวกัน คำตอบจึงไม่เผยว่าอีเมลไหนมีอยู่จริง · login สำเร็จแล้วล้างตัวนับของอีเมลนั้น แต่ไม่ล้างตัวนับของ IP
*   **สมัครสมาชิก:** นับทุกคำขอที่ผ่าน validation ต่อ IP ทั้ง `201` และ `409` เพราะ `409` คือคำตอบที่เผยว่าใครมีบัญชี · ค่า default 20 ครั้งต่อชั่วโมง พอให้ทั้งห้องเรียนสมัครพร้อมกันจากเน็ตมหาวิทยาลัยได้ · คำขอที่ไม่ผ่าน validation (`400`) ไม่นับ
*   IP ของผู้ใช้คือค่า **ขวาสุด** ของ `X-Forwarded-For` ซึ่ง proxy ตัวที่อยู่หน้า service เป็นคนใส่ (nginx ต่อท้าย, Vercel เขียนทับทั้ง header) ไม่ใช่ค่าซ้ายสุดที่ client เขียนมาเองได้
*   เพดานและหน้าต่างเวลาอ่านจาก environment (`AUTH_LOGIN_MAX_FAILS_PER_EMAIL`, `AUTH_LOGIN_MAX_FAILS_PER_IP`, `AUTH_LOGIN_WINDOW_MINUTES`, `AUTH_REGISTER_MAX_PER_IP`, `AUTH_REGISTER_WINDOW_MINUTES`) โดยมีค่า default ตามข้างบน · ค่าที่ไม่ใช่จำนวนเต็มบวกทำให้ service ไม่ยอมสตาร์ต แทนที่จะปิด limit ไปเงียบ ๆ · แถวที่เก่ากว่าหน้าต่างที่ยาวที่สุดถูกลบทุกครั้งที่บันทึกครั้งใหม่
*   ไม่เลือกตัวนับใน memory และ Vercel Firewall: memory ใช้ข้าม instance ของ Vercel ไม่ได้ ส่วน firewall ไม่ครอบคลุม `docker compose` และเทสต์

**ผลที่ตามมา:**
*   การเดารหัสผ่านช้าลงเหลือไม่กี่ครั้งต่อบัญชีต่อ 15 นาที และใช้หน้าสมัครไล่เช็คอีเมลเป็นพัน ๆ ไม่ได้อีก
*   คนที่รู้อีเมลของนักศึกษาคนหนึ่งทำให้บัญชีนั้น login ไม่ได้ 15 นาทีได้ด้วยการกรอกผิด 5 ครั้ง · หน้าต่างสั้นทำให้เป็นแค่ความรำคาญ ไม่มีการล็อกถาวร
*   นักศึกษาหลายคนหลัง IP เดียวของมหาวิทยาลัยใช้เพดานต่อ IP ร่วมกัน จึงตั้งเพดานต่อ IP ไว้สูงกว่าต่ออีเมลมาก และปรับเพิ่มผ่าน environment ได้
*   login และสมัครแต่ละครั้งมี query เล็ก ๆ เพิ่ม 1–2 ครั้ง และ login ที่ไม่ผ่านเขียนแถวลงฐานข้อมูล
*   ฟอร์ม login และสมัครบนหน้าเว็บแสดงข้อความของ service ตอนได้ `429` แทนข้อความ error ทั่วไปของ HTTP
