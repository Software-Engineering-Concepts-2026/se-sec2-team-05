# ADR-008: ให้เจ้าของที่ login อยู่แก้และลบโน้ตของตัวเองได้ โดยยังใช้ edit token ควบคู่

[🌐 English](./0008-owner-login-for-note-changes.md) · **ภาษาไทย**

**สถานะ:** Accepted · แก้ไขเพิ่มเติม [ADR-004](./0004-per-note-edit-token.th.md) · ตั้งแต่ [ADR-013](./0013-retire-per-note-edit-token.th.md) การ login เป็นเจ้าของเป็นทางเดียว edit token ถูกเอาออกแล้ว

**บริบท:**
[ADR-004](./0004-per-note-edit-token.th.md) ให้ edit token ต่อโน้ตเป็นทางเดียวที่จะแก้หรือลบโน้ตได้ ระหว่างที่ทีมยังไม่มีระบบบัญชี ตอนนี้มีแล้ว: [ADR-005](./0005-auth-jwt-with-server-side-sessions.th.md) เพิ่ม `auth-service` และตั้งแต่ US-31 (#31) การอัปโหลดทุกครั้งต้อง login และเก็บ id ของบัญชีผู้อัปโหลดไว้ใน `notes.uploader_id` (คอลัมน์ `NOT NULL`)

ดีไซน์หน้าโปรไฟล์ (Issue #82, wireframe หน้า 1e) มีรายการ "My uploads" ที่มีปุ่มแก้และลบทุกแถว ถ้ามีแค่ ADR-004 หน้านี้ทำงานไม่ได้ เพราะ token ถูกส่งกลับครั้งเดียวตอนอัปโหลด เซิร์ฟเวอร์เก็บแค่ hash และผู้ใช้ที่ไม่ได้จดไว้จะแก้โน้ตนั้นไม่ได้อีกเลย การให้ผู้ใช้วาง token ทุกครั้งก่อนแก้คือภาระที่ ADR-004 เองบอกไว้ว่าระบบ auth จริงจะมาช่วยเอาออก

ADR-004 วางแผนไว้ว่าจะลบ token ทิ้งเมื่อมีระบบบัญชี แต่ถ้าลบตอนนี้ client ที่ใช้ `X-Note-Token` อยู่แล้วจะพัง (smoke test DK-03 ถึง DK-06 ใน CI และ token ที่ผู้ใช้เก็บไว้) ADR นี้จึง**เพิ่ม**ทางของบัญชีเข้าไป ไม่ได้เอาทางของ token ออก

**การตัดสินใจ:**
`PATCH /notes/<id>` และ `DELETE /notes/<id>` รับหลักฐานความเป็นเจ้าของ**อย่างใดอย่างหนึ่ง**:

1.  `X-Note-Token` ที่ถูกต้องของโน้ตนั้น (ADR-004 เหมือนเดิม)
2.  `Authorization: Bearer <access_token>` ของบัญชีที่ id ตรงกับ `notes.uploader_id`

ลำดับการตรวจและ response:

*   ตรวจ edit token ก่อน ถ้าตรงก็ผ่านเลยโดยไม่เรียก `auth-service` คนที่มี token จึงยังแก้ได้แม้ `auth-service` ล่ม
*   ไม่มี token ที่ถูกและไม่มี header `Authorization` ได้ `403 forbidden` เหมือนเดิม
*   ส่ง Bearer ที่ `auth-service` ไม่รับ ได้ `401 unauthorized` พร้อม `WWW-Authenticate: Bearer` หน้าเว็บจะได้รู้ว่าต้องพาไป login ใหม่ ถ้าเรียก `auth-service` ไม่ถึงได้ `503 auth_unavailable`
*   login ถูกแต่ไม่ใช่ผู้อัปโหลด ได้ `403 forbidden`
*   โน้ตที่ไม่มีอยู่ยังได้ `404` ก่อนตรวจสิทธิ์ใดๆ

`uploader_id` ตัวเดียวกันนี้ใช้กับ endpoint อ่านใหม่ `GET /notes/mine` (ต้อง login) ที่คืนโน้ตของผู้เรียกพร้อมสรุปยอดสำหรับหน้าโปรไฟล์ ส่วนค่า `uploader_id` เองยังไม่ถูกส่งออกใน response ใด

**ผลที่ตามมา:**
*   **ด้านบวก:**
    *   หน้าโปรไฟล์มีปุ่มแก้และลบได้ โดยผู้ใช้ไม่ต้องเก็บ token
    *   ทำ token หายไม่ใช่ทางตันอีกต่อไปสำหรับโน้ตที่อัปโหลดด้วยบัญชี ซึ่งก็คือทุกโน้ตตั้งแต่ US-31
    *   client และเทสต์ที่ใช้ token อยู่ยังทำงานได้ มีเทสต์เก่าตัวเดียวที่ต้องแก้ คือตัวที่ยืนยันว่า login อย่างเดียวไม่พอ
*   **ด้านลบ:**
    *   ตอนนี้มีสองทางเข้า edit token ที่หลุดไปยังแก้/ลบโน้ตนั้นได้ แม้เจ้าของบัญชีจะเปลี่ยนรหัสผ่านแล้ว การเพิกถอน token ยังอยู่นอกขอบเขต
    *   ความเป็นเจ้าของผ่านการ login มีข้อจำกัดเดียวกับ ADR-005 คือยังไม่มีการยืนยันอีเมล และ `notes-service` เชื่อคำตอบของ `auth-service` จาก `GET /auth/me`
    *   การลบ token ทิ้งในอนาคต (แผนเดิมของ ADR-004) ยังเป็นการตัดสินใจแยกต่างหาก และต้องให้หน้าเว็บกับ smoke test เลิกส่ง `X-Note-Token` ก่อน
