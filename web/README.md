# Web app — ค้นหา, เข้าสู่ระบบ, อัปโหลดโน้ต + gateway

หน้าเว็บตัวจริงตัวแรกของ NoteShare ที่ต่อกับ API จริง (ต่างจาก `prototypes/sprint1/` ที่เป็น mockup ข้อมูล hardcode
และเก็บไว้เป็นหลักฐาน Lab 4 ไม่ได้แก้) เสิร์ฟผ่าน nginx ที่ทำหน้าที่ gateway ด้วย ดูเหตุผลใน
[ADR-006](../docs/architecture/adr/0006-nginx-web-gateway.th.md)

## ทำอะไรได้

- **ค้นหา/กรองโน้ต** ผ่าน `GET /notes` จริง: คำค้น (`q`), คณะ, ชั้นปี 1–8, หัวข้อ (`topic`), ช่วงวันที่เรียน,
  ประเภทไฟล์ (PDF/PNG/JPG เลือกได้หลายแบบ) และการเรียง (`new`, `old`, `class_date`, `title`, `rating` = คะแนนสูงสุดก่อน, Issue #83)
  - ตัวกรองถูกเก็บใน URL — reload หรือกด back แล้วได้ผลค้นหาเดิม แชร์ลิงก์ผลค้นหาได้
  - API ส่ง `count` เป็นจำนวนในหน้านั้น ไม่ใช่ยอดรวม หน้าเว็บจึงใช้ปุ่ม "โหลดเพิ่ม" ทีละ 20 รายการ
    แทนเลขหน้า และซ่อนปุ่มเมื่อได้หน้าที่ไม่เต็ม
  - ค่าที่ API ไม่รับ (`400 invalid_filter`) แสดงเป็นข้อความในหน้าพร้อมชื่อช่องที่ผิด ไม่ใช้ `alert()`
- **ชื่อผู้อัปโหลดอยู่บนการ์ดทุกใบและในหน้าตัวอย่าง** — US-31 AC3 (#31)
- **ดูตัวอย่างก่อนดาวน์โหลด** — กด "ดูตัวอย่าง" แล้วเปิด `<dialog>` ทับผลค้นหา แสดงภาพจาก
  `/notes/<id>/preview` พร้อมปุ่มดาวน์โหลดไฟล์เต็ม ปิดได้ทั้งปุ่ม ✕, Esc และคลิกฉากหลัง ผลค้นหาและตำแหน่ง
  scroll ไม่ถูกแตะ และ focus กลับไปที่ปุ่มที่กดเปิด — US-11 AC3 (#11)
  - preview ที่สร้างไม่ได้ (`422 preview_unavailable`) หรือโน้ตถูกลบ (`404`) แสดงเหตุผลแทนรูปแตก
  - การเปิด preview จะเรียก `GET /notes/<id>` ทุกครั้ง จึงทำให้ `view_count` ของ Note เพิ่มขึ้นทุกครั้งที่เปิด preview รวมถึงผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบ
- **ให้คะแนนโน้ต** — การ์ดค้นหาและหน้า preview แสดงค่าเฉลี่ยและจำนวนผู้ให้คะแนน โน้ตที่เปิด preview ขณะ login
  จะบันทึกสิทธิ์และให้เลือกคะแนน 1–5 ดาวใน preview ได้ คะแนนครั้งถัดไปของสมาชิกคนเดิมจะอัปเดตคะแนนเดิม
  ผู้ใช้ที่ยังไม่ได้ login เห็นค่าเฉลี่ยได้ แต่ต้อง login แล้วเปิดหรือดาวน์โหลดโน้ตก่อนจึงจะส่งคะแนนได้ (Issue #13)
- **สมัครสมาชิกและเข้าสู่ระบบ** ที่ `/login.html` (แท็บ "เข้าสู่ระบบ" / "สมัครสมาชิก", เปิดแท็บสมัครตรง ๆ ด้วย `#register`)
  ผ่าน `POST /auth/register` และ `POST /auth/login` — US-05 (#5), US-06 (#6)
  - เหตุผลที่ผิดแสดงใต้ช่องนั้นจาก `fields` ที่ auth-service ส่งมา (เช่น ต้องเป็นอีเมล `@up.ac.th`, รหัสผ่านอย่างน้อย 8 ตัว)
  - สมัครสำเร็จแล้วเข้าสู่ระบบต่อให้ทันทีด้วยข้อมูลชุดเดิม ไม่ต้องกรอกซ้ำ
  - login ผิดได้ข้อความกลาง ๆ จาก service ("อีเมลหรือรหัสผ่านไม่ถูกต้อง") ไม่บอกว่าผิดช่องไหน (AC3 ของ #6)
  - เข้าสู่ระบบแล้วกลับไปหน้าเดิมตาม `?next=` ซึ่งรับแค่ `/`, `/index.html`, `/upload.html`, `/note.html`, `/profile.html`, `/admin.html`, `/stats.html` ของเว็บนี้เท่านั้น
    ลิงก์ที่ชี้ไปเว็บอื่นจะพากลับหน้าค้นหาแทน (กัน open redirect)
- **แถบเมนูบนทุกหน้า** แสดงลิงก์ "สถิติ" ชื่อผู้ใช้ ลิงก์ "โปรไฟล์" และปุ่ม "ออกจากระบบ" หรือปุ่ม "เข้าสู่ระบบ" ถ้ายังไม่ได้เข้า · ออกจากระบบเรียก
  `POST /auth/logout` ให้ token ใช้ไม่ได้ทันทีที่ฝั่ง server (ADR-005) แล้วล้างใน browser
- **อัปโหลดโน้ต** ที่ `/upload.html` ผ่าน `POST /notes` แบบ multipart — US-08 (#8), US-31 (#31)
  - ยังไม่ได้เข้าสู่ระบบจะถูกพาไปหน้าเข้าสู่ระบบก่อน แล้วกลับมาหน้านี้
  - ฟอร์มตรวจทุกช่องก่อนส่งตามกฎเดียวกับ `services/notes-service/validation.py` (ช่องบังคับ, ความยาว, ชั้นปี 1–8,
    วันที่, PDF/PNG/JPG ไม่เกิน 4 MB) จะได้ไม่ต้องส่งไฟล์ใหญ่ไปแล้วค่อยรู้ว่าผิด · service ยังตรวจซ้ำทุกครั้ง
    และถ้าผลไม่ตรงกัน หน้าเว็บจะแสดงคำตอบของ service
  - หน้าบอกล่วงหน้าว่าโน้ตจะแสดงชื่อผู้อัปโหลดอะไร (ชื่อจากบัญชี ไม่มีช่องให้กรอกชื่อเอง)
  - อัปโหลดเสร็จแล้วแสดง **รหัสแก้ไขโน้ต** (`edit_token`) พร้อมปุ่มคัดลอกและคำเตือนว่าเห็นได้ครั้งเดียว เพราะ service เก็บไว้แค่ hash
    (ADR-004) · กด "อัปโหลดอีกไฟล์" แล้วรหัสหายจากหน้าจอ · ใต้รหัสมีลิงก์ไปหน้าแก้ไขด้วยรหัสของโน้ตนั้น (`edit.html?id=<id>`)
  - ถ้า session ถูกเพิกถอนระหว่างกรอก (เช่น ออกจากระบบจากอีกแท็บ) จะได้ `401` แล้วแสดงลิงก์เข้าสู่ระบบใหม่ โดยข้อมูลที่กรอกยังอยู่
  - **แถบความคืบหน้า** ระหว่างส่งไฟล์ (Issue #85) บอกเป็นเปอร์เซ็นต์และ MB · ส่งด้วย `XMLHttpRequest` แทน `fetch`
    เพราะ `fetch` บอกไม่ได้ว่าส่ง body ไปแล้วเท่าไร · ส่งครบแล้วขึ้น "รอเซิร์ฟเวอร์บันทึกโน้ต" จนได้คำตอบ
- **หน้าโปรไฟล์** ที่ `/profile.html` (wireframe 1e, Issue #85) — ต้องเข้าสู่ระบบ ยังไม่เข้าจะถูกพาไปหน้าเข้าสู่ระบบแล้วกลับมา
  - การ์ดสรุป 5 ช่องจาก `summary` ของ `GET /notes/mine`: จำนวนโน้ต คะแนนเฉลี่ย (ถ่วงตามจำนวนคะแนน) ดาวน์โหลด เปิดดู
    และคำขอบคุณ นับจากโน้ตทุกตัว ไม่ใช่แค่หน้าที่โหลดมา
  - **โน้ตของฉัน** ใหม่สุดก่อน โหลดเพิ่มทีละ 20 · ชื่อโน้ตลิงก์ไปหน้ารายละเอียด (`note.html`, PR #88) · ปุ่ม "สถิติ" ไปที่ `stats.html?id=<id>`
  - **แก้ไข** เปิดฟอร์มใน `<dialog>` ที่มีช่องเดียวกับหน้าอัปโหลด (ไม่มีไฟล์) ตรวจด้วยกฎเดียวกัน แล้วส่ง `PATCH /notes/<id>`
    เฉพาะช่องที่เปลี่ยน ล้างช่องไม่บังคับได้ด้วยการลบค่าออก · **ลบ** ถามยืนยันใน `<dialog>` ก่อน `DELETE /notes/<id>`
    · ทั้งสองอย่างใช้ token ของบัญชีเจ้าของ (ADR-008) ไม่ต้องใช้รหัสแก้ไข
  - **รายการโปรด** จาก `GET /notes/favorites` พร้อมปุ่มเอาออก
  - token ถูกเพิกถอนตอนโหลดรายการ → ไปหน้าเข้าสู่ระบบ · ถ้าเกิดตอนกดบันทึกใน dialog จะแสดงลิงก์เข้าสู่ระบบแทน ข้อมูลที่แก้ยังอยู่

- **หน้ารายละเอียดโน้ต** ที่ `/note.html?id=<id>` (wireframe 1d, Issue #85) — เปิดจากชื่อโน้ตบนการ์ด หรือปุ่ม
  "เปิดหน้าโน้ต" ใน preview · ส่วน "ดูตัวอย่าง" ยังเป็น `<dialog>` แบบเดิมไว้ดูเร็ว ๆ
  - แสดง metadata ทั้งหมด คำอธิบาย ภาพตัวอย่าง และลิงก์ "กลับไปหน้าค้นหา" ที่พากลับไปผลค้นหาเดิม (ถ้ามาจากหน้าค้นหา)
  - **ดาวน์โหลด** ใช้ `fetch` พร้อม token แล้วบันทึกไฟล์ผ่านลิงก์ชั่วคราว แทน `<a href>` ธรรมดา เพื่อให้นับเป็นการเปิดของ
    ผู้ใช้คนนั้น (สิทธิ์ให้คะแนน, Issue #13) และหน้าเว็บรู้ว่าดาวน์โหลดแล้ว
  - **รายการโปรด** (US-15) ปุ่มสลับ `POST`/`DELETE /notes/<id>/favorite` · **รายงาน** (Issue #17) เปิดฟอร์มกรอกเหตุผล
    ไม่เกิน 500 ตัวอักษร รายงานซ้ำได้ข้อความว่ารายงานไปแล้ว ซ่อนปุ่มนี้กับโน้ตของตัวเอง
  - **ให้คะแนน** (Issue #13) แบบเดียวกับ preview · **ขอบคุณเจ้าของโน้ต** (US-28) ปุ่มขึ้นหลังดาวน์โหลดในแท็บนี้เท่านั้น
    เพราะ API ไม่ได้ตรวจเงื่อนไข "หลังดาวน์โหลด" หน้าเว็บจึงจำไว้ใน `sessionStorage` (key `noteshare.downloaded`, แยกตามผู้ใช้)
    · โน้ตของตัวเองหรือขอบคุณแล้วจะไม่มีปุ่ม
  - **ความคิดเห็น** (Issue #14) ใหม่สุดอยู่บน โพสต์ได้ไม่เกิน 1000 ตัวอักษร ลบได้เฉพาะของตัวเอง · API ส่งแค่ `user_id`
    ไม่มีชื่อผู้เขียน หน้าเว็บจึงแสดง "คุณ" กับความคิดเห็นของตัวเอง และ "สมาชิก" กับของคนอื่น · เวลาแสดงเป็นเวลาไทยและปี พ.ศ.
    (บน SQLite service ส่งเวลาแบบไม่มี timezone มา หน้าเว็บถือว่าเป็น UTC เหมือนที่ service เก็บ)
  - ทุกการกระทำที่ต้อง login แสดงลิงก์เข้าสู่ระบบที่พากลับมาหน้าเดิม · ถ้า token ถูกเพิกถอนระหว่างใช้งาน (`401`)
    หน้าเว็บล้าง session แล้วทุกกล่องเปลี่ยนเป็นสถานะยังไม่ login พร้อมกัน
  - การเปิดหน้านี้เรียก `GET /notes/<id>` จึงนับ `view_count` เหมือนการเปิด preview
  - ท้ายแถบด้านข้างมีลิงก์ "แก้หรือลบโน้ตนี้ด้วยรหัส" ไปหน้าแก้ไขด้วยรหัส

- **หน้าสถิติ** ที่ `/stats.html` (Issue #16, US-28 AC3) — ตัวเลขทั้งหมดมาจาก **stats-service** ผ่าน gateway
  - **ภาพรวมทั้งระบบ** จาก `GET /stats` ดูได้โดยไม่ต้อง login: จำนวนโน้ต ยอดดาวน์โหลดรวม จำนวนผู้แบ่งปัน และ 5 อันดับผู้แบ่งปัน
    ที่มียอดดาวน์โหลดสูงสุด · API ส่งแค่ `owner_id` ไม่มีชื่อ หน้าเว็บจึงแสดง "คุณ" กับอันดับของตัวเอง และ "สมาชิก" กับคนอื่น
    แทนการโชว์เลขบัญชีของคนอื่น · ถ้า login และเคยแบ่งปันโน้ต จะมีกล่องบอกอันดับของตัวเอง
  - **สถิติโน้ตของฉัน** (ต้อง login) รายการจาก `GET /notes/mine` แล้วขอตัวเลขของแต่ละโน้ตจาก `GET /notes/<id>/stats`:
    เปิดดู ดาวน์โหลด (แยกกันตาม AC2 ของ #16) และจำนวนคำขอบคุณ · โหลดเพิ่มทีละ 20 · หน้านี้ไม่เรียก `GET /notes/<id>`
    จึงไม่ทำให้ `view_count` เพิ่ม
  - `?id=<id>` (จากปุ่ม "สถิติ" ในหน้าโปรไฟล์) ไฮไลต์โน้ตนั้นแล้วเลื่อนไปหา ถ้าโน้ตนั้นยังไม่อยู่ในหน้าที่โหลดมาจะแสดงไว้บนสุดก่อน
    · stats-service ยังตรวจความเป็นเจ้าของเอง id ของโน้ตคนอื่นได้ข้อความ "ดูสถิติได้เฉพาะโน้ตที่คุณอัปโหลด" ในแถวนั้น
  - stats-service ตอบ error เป็นข้อความของตัวเอง (ไม่ใช่รหัสแบบ notes-service) หน้าเว็บจึงแปลตาม status · token ถูกเพิกถอน → ส่วนของฉัน
    เปลี่ยนเป็นลิงก์เข้าสู่ระบบ ส่วนภาพรวมยังอยู่
  - gateway ส่ง `/stats` และ `/notes/<ตัวเลข>/stats` ไปที่ stats-service:5000 ด้วย `location` แบบ regex ซึ่ง nginx เลือกก่อน prefix `/notes/`
    ส่วน `/notes/<id>` อื่น ๆ ยังไป notes-service · `web` จึง `depends_on` stats-service ด้วย เพราะ nginx resolve ชื่อ upstream ตอนสตาร์ต

- **หน้าตรวจรายงานของผู้ดูแล** ที่ `/admin.html` (Issues #17, #18) — ต้องเข้าสู่ระบบด้วยบัญชีที่อยู่ใน `ADMIN_USER_IDS`
  ของ notes-service (ADR-007)
  - รายงานจาก `GET /reports` รวมเป็นการ์ดละหนึ่งโน้ต เรียงตามรายงานล่าสุด แต่ละการ์ดมีชื่อโน้ต (ลิงก์ไปหน้ารายละเอียด)
    วิชา ผู้อัปโหลด และรายงานทุกข้อพร้อมชื่อผู้รายงาน เวลาไทย และเหตุผล
  - **ยกเลิกรายงานนี้** เรียก `DELETE /reports/<id>` (โน้ตยังอยู่) · **ลบโน้ตนี้** ถามยืนยันใน `<dialog>` ก่อน
    `DELETE /reports/<id>/note` ซึ่งลบโน้ต ไฟล์ และรายงานทั้งหมดของโน้ตนั้น · ได้ `404` (ผู้ดูแลอีกคนจัดการไปแล้ว) ถือว่าเสร็จ
  - สมาชิกทั่วไปที่เปิดหน้านี้ได้ `403` และเห็นข้อความว่าหน้านี้สำหรับผู้ดูแลเท่านั้น · token ถูกเพิกถอนระหว่างใช้ → ไปหน้าเข้าสู่ระบบ
  - **ทางเข้า:** หน้าเว็บไม่รู้ล่วงหน้าว่าใครเป็นผู้ดูแล เพราะ auth-service ไม่มี role (ADR-007) หน้าโปรไฟล์จึงเรียก `GET /reports`
    หนึ่งครั้ง ได้ `200` ถึงจะแสดงลิงก์ "ตรวจรายงานโน้ต (ผู้ดูแล)" · สมาชิกทั่วไปจะเห็น `403` ของ request นี้ใน DevTools ซึ่งเป็นเรื่องปกติ
  - `/reports` ไม่ได้ขึ้นต้นด้วย `/notes` จึงเพิ่ม `location` ใน `nginx.conf` ให้ส่งต่อไปที่ notes-service

- **หน้าแก้/ลบด้วยรหัสแก้ไข** ที่ `/edit.html?id=<id>` (US-19, US-20 ด้วย edit token ตาม ADR-004) — ไม่ต้องเข้าสู่ระบบ
  - โหลดโน้ตด้วย `GET /notes/<id>` (นับเป็นการเปิดดูเหมือนหน้ารายละเอียด) แล้วให้กรอกรหัสแก้ไขที่ได้ตอนอัปโหลด
  - **ตรวจรหัสก่อนเปิดฟอร์ม:** ไม่มี endpoint สำหรับตรวจรหัสโดยตรง หน้าเว็บจึงส่ง `PATCH /notes/<id>` ที่ไม่มีฟิลด์ service ตรวจรหัสก่อน
    แล้วจึงพบว่าไม่มีอะไรให้แก้ ได้ `400 no_fields_to_update` = รหัสถูกและไม่มีข้อมูลถูกเขียน · `403` = รหัสผิด (แสดงใต้ช่องรหัส)
    · `404` = โน้ตถูกลบไปแล้ว · request นี้จึงขึ้นเป็น `400` ใน DevTools ซึ่งเป็นเรื่องปกติ
  - รหัสถูกแล้วเปิดฟอร์มเดียวกับหน้าโปรไฟล์ (ตรวจด้วยกฎเดียวกัน ส่งเฉพาะช่องที่เปลี่ยน) และปุ่ม **ลบโน้ตนี้** ที่ถามยืนยันใน `<dialog>` ก่อน
    `DELETE /notes/<id>` · ลบแล้วแสดงกล่อง "ลบโน้ตแล้ว" พร้อมลิงก์ไปหน้าค้นหา
  - ส่งรหัสใน header `X-Note-Token` อย่างเดียว **ไม่ส่ง `Authorization`** แม้จะเข้าสู่ระบบอยู่ เพราะ notes-service ให้เจ้าของที่ login
    ผ่านได้ด้วย (ADR-008) ถ้าส่งไปด้วย รหัสที่ผิดจะดูเหมือนถูกสำหรับเจ้าของ · รหัสเก็บไว้ในตัวแปรของหน้าเท่านั้น ไม่ลง `sessionStorage`/`localStorage`
    reload แล้วต้องกรอกใหม่
  - เจ้าของที่เข้าสู่ระบบอยู่ยังแก้/ลบจากหน้าโปรไฟล์ได้โดยไม่ต้องใช้รหัส (ADR-008) หน้านี้มีไว้สำหรับคนที่ถือรหัส

## เก็บ token ไว้ที่ไหน

หลังเข้าสู่ระบบ หน้าเว็บเก็บ `access_token`, `expires_at` และชื่อผู้ใช้ไว้ใน **`sessionStorage`** (key `noteshare.session`)

- **ไม่ใช้ `localStorage`** เพราะ token อยู่ได้ถึง 8 ชั่วโมง (`AUTH_TOKEN_TTL_HOURS`) ถ้าเก็บแบบข้ามการปิด browser
  เครื่องที่ใช้ร่วมกัน (เช่นห้องคอมพิวเตอร์ของมหาวิทยาลัย) จะยัง login ค้างอยู่หลังผู้ใช้ปิดหน้าต่างไป · `sessionStorage` หายเมื่อปิดแท็บ
  แต่ยังอยู่เมื่อเปลี่ยนหน้าในแท็บเดิม ซึ่งพอสำหรับเว็บหลายหน้าแบบนี้
- **ไม่เก็บไว้ในหน่วยความจำอย่างเดียว** เพราะเว็บนี้แยกเป็นหลายหน้า เปลี่ยนหน้าแล้ว token จะหาย
- **ข้อจำกัดที่ยอมรับ:** script ที่รันบนหน้าเดียวกันอ่าน `sessionStorage` ได้ ถ้ามีช่องโหว่ XSS token จะรั่วได้ จึงต้อง escape ทุกค่าที่มาจากผู้ใช้
  (`escapeHtml` ใน `search-utils.js` และ `textContent` ในแถบเมนู/หน้าอัปโหลด) · ทางที่ปลอดภัยกว่าคือ cookie แบบ `HttpOnly`
  แต่ต้องแก้ auth-service และเพิ่มการกัน CSRF จึงยังไม่ทำในรอบนี้
- session ที่หมดอายุตาม `expires_at` หรืออ่านไม่ออกจะถูกลบทิ้งตอนโหลดหน้า และ API ที่ตอบ `401` ทำให้หน้าเว็บล้าง session ด้วย

## หน้าตา

ตาม mockup ที่อติชาติออกแบบ ([`docs/design/`](../docs/design/README.md), Issue #84): พื้นสีกระดาษ ตัวอักษรสีหมึก สีเน้นอำพัน หัวข้อเป็นตัวมีเชิง
การ์ดโน้ตเรียงเป็น grid · หน้าค้นหามี hero, ช่องค้นหาแบบแถบเดียว และพับตัวกรองไว้ใน `<details>`
(กางออกเองเมื่อ URL มีตัวกรอง) · หน้าเข้าสู่ระบบเป็นการ์ดสองคอลัมน์ · ช่องเลือกไฟล์ของหน้าอัปโหลดวาดเป็น drop zone
แต่ยังเป็น `<input type="file">` ตัวจริง จึงใช้คีย์บอร์ดและลากไฟล์มาวางได้โดยไม่ต้องมีสคริปต์เพิ่ม

- **ฟอนต์** โหลดจาก Google Fonts: Newsreader + Noto Serif Thai (หัวข้อ), Work Sans + IBM Plex Sans Thai (เนื้อหา)
  Newsreader กับ Work Sans ไม่มีตัวอักษรไทย จึงมีฟอนต์ไทยต่อท้ายในแต่ละชุด ตัวอังกฤษมาจากฟอนต์แรก ตัวไทยมาจากฟอนต์ที่สอง
  ถ้าโหลด Google Fonts ไม่ได้ หน้าเว็บยังใช้งานได้ด้วยฟอนต์ของระบบ (Georgia / Segoe UI / Tahoma)
- **สี** ประกาศเป็นตัวแปรใน `:root` ของ `style.css` ที่เดียว
- ไม่ได้ทำปุ่ม SSO/Google, ระบบ tag และไฟล์ DOCX ที่อยู่ใน mockup เพราะอยู่นอกขอบเขตของระบบ

## วิธีรัน

```bash
docker compose up -d --build
# เปิด http://localhost:8080
```

ทุก request ของหน้าเว็บเป็น URL แบบ relative ไปที่ origin เดียวกัน (`/notes?…`) จึง**ต้องเปิดผ่าน gateway**
ถ้าเปิด `index.html` จากดิสก์ตรง ๆ browser จะบล็อกการเรียก API เพราะ service ไม่ได้เปิด CORS

ถ้ายังไม่มีโน้ตให้ค้น ให้สมัครที่ http://localhost:8080/login.html#register แล้วอัปโหลดที่ `/upload.html`
หรือยิง API ผ่าน gateway ตรง ๆ ก็ได้ (เช่นตอนเตรียมข้อมูลทีละหลายโน้ต):

```bash
curl -X POST http://localhost:8080/auth/register -H 'Content-Type: application/json' \
  -d '{"email":"me@up.ac.th","password":"choose a password","display_name":"My Name"}'
token=$(curl -s -X POST http://localhost:8080/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"me@up.ac.th","password":"choose a password"}' | jq -r .access_token)
curl -X POST http://localhost:8080/notes -H "Authorization: Bearer $token" \
  -F title='Linked List' -F subject_name='Data Structures' -F subject_code=CS201 \
  -F faculty=ICT -F year_level=2 -F lesson='Linked List' -F 'file=@note.pdf;type=application/pdf'
```

> บน Windows ถ้าส่งชื่อภาษาไทยผ่าน `curl -F` ใน Git Bash ตัวอักษรอาจกลายเป็น `?` ตั้งแต่ฝั่ง client
> (เจอตอนทดสอบ) — ไม่ใช่บั๊กของ service · ส่งจาก Python/Postman หรือ terminal ที่เป็น UTF-8 แทน
