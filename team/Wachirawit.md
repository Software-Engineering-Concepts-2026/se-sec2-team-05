Pragmatic Promise
จะเขียน Commit message ในรูปแบบ Conventional Commitsตามที่กำหนดให้ชัดเจน จะส่งมอบงานตามกำหนดหากพบปัญหาจะติดต่อและปรึกษากับทีม

ทำไมอยากเรียน SE
ที่ผ่านมาเวลาทำโปรเจกต์กลุ่มมักจะเจอปัญหาเวลาต้องรวมโค้ดหรือจัดการไฟล์งานที่แต่ละคนเขียน จึงอยากเรียนรู้กระบวนการทาง Software Engineering เพื่อนำแนวปฏิบัติที่ถูกต้องมาใช้จัดการโปรเจกต์ ลดความซ้ำซ้อน และทำให้ทีมพัฒนาซอฟต์แวร์ร่วมกันได้อย่างราบรื่น

Broken Window ที่เคยเจอ
Window คือ: การ Copy-Paste โค้ด UI แผงใหญ่ๆ (เช่น การ์ดแสดงข้อมูล หรือ ฟอร์มกรอกข้อมูล) ไปแปะอีกหน้าหนึ่งทั้งหน้าเพราะความมักง่าย แทนที่จะสละเวลาเขียนแยกเป็น Reusable Component

ผลกระทบ:พอเริ่มก็อปวางจุดนึง ก็ติดนิสัยมักง่ายทำแบบเดิมกับหน้าอื่นๆ ไปเรื่อยๆ พอต้องมาแก้ดีไซน์แค่จุดเดียว ต้องมาแก้ซ้ำๆหลายหน้าทำให้ UI ฟังก์ชันเดียวกันมี UI ไม่เหมือนกันเมื่อย้ายหน้าเพราะแก้ไม่ครบทุกหน้า

ถ้าแก้ทันทีจะป้องกันอะไร: ถ้าคัดแยกโค้ดเป็น Component กลางตั้งแต่แรก เวลาแก้โค้ดจุดเดียวก็จะอัปเดตตามกันทั้งโปรเจกต์ ป้องกันการสะสมปัญหาทางเทคนิคให้ตัวเอง และช่วยประหยัดเวลามากเวลาต้องกลับมาอัปเดตหรือแก้บั๊ก
